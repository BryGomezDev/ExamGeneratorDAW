PREGUNTA: En el contexto de XML, el término Case Sensitive se refiere a:
A: Cualidad que permite referenciar elementos DTD.
B: Propiedad que permite distinguir entre mayúsculas y minúsculas.
C: Cualidad de los elementos de consulta que permite asignar valores.
D: Ninguna de las anteriores es correcta.
RESPUESTA: B
EXPLICACION: XML es case sensitive, lo que significa que distingue entre mayúsculas y minúsculas en los nombres de etiquetas y atributos. Así, <Libro>, <libro> y <LIBRO> son tres etiquetas completamente distintas. Esto contrasta con HTML, que no es case sensitive. Por ello, las etiquetas de apertura y cierre deben usar exactamente el mismo uso de mayúsculas: <Autor> no puede cerrarse con </autor>.

PREGUNTA: ¿Cuál no es una herramienta de creación y edición de XML?
A: Stylus Studio.
B: Oxygen XML.
C: Excharger XN1L Editor.
D: Todas las anteriores son herramientas de creación y edición de XML.
RESPUESTA: D
EXPLICACION: Las tres opciones son editores XML especializados reales. Stylus Studio es un IDE para XML/XSLT/XQuery. Oxygen XML Editor es uno de los editores XML más completos del mercado, con soporte para DTD, XML Schema, XSLT y XPath. Excharger XN1L Editor también es un editor XML. Por eso la respuesta correcta es que todas son herramientas válidas de creación y edición XML.

PREGUNTA: Del lenguaje XML surgieron otros como:
A: XHTML.
B: MathML.
C: SVG.
D: Todos los anteriores son correctos.
RESPUESTA: D
EXPLICACION: XML es un metalenguaje que sirve de base para definir otros lenguajes de marcas. XHTML es la reformulación de HTML 4 usando sintaxis XML estricta. MathML (Mathematical Markup Language) representa fórmulas matemáticas en XML. SVG (Scalable Vector Graphics) describe gráficos vectoriales en XML. Los tres son vocabularios XML estandarizados por el W3C, por lo que todos son correctos.

PREGUNTA: DTD es:
A: Un sistema numérico.
B: Un tipo de atributo.
C: Un documento de verificación.
D: Un tipo de etiqueta.
RESPUESTA: C
EXPLICACION: DTD (Document Type Definition) es un documento que define la estructura y las reglas de un documento XML: qué elementos pueden aparecer, en qué orden, cuántas veces y qué atributos tienen. Actúa como esquema de verificación: permite comprobar que un documento XML es válido (no solo bien formado). Puede declararse internamente dentro del propio XML o en un archivo externo con extensión .dtd.

PREGUNTA: El prólogo del documento XML se marca con:
A: <= ... =>.
B: <" ... ">.
C: <? ...?>.
D: < ... >.
RESPUESTA: C
EXPLICACION: El prólogo de un documento XML se escribe con la sintaxis <?xml version="1.0" encoding="UTF-8"?>, usando los delimitadores <? y ?>. Esta declaración es una instrucción de procesamiento que informa al parser sobre la versión de XML utilizada y la codificación de caracteres. Aunque técnicamente opcional, se recomienda incluirla siempre como primera línea del documento.

PREGUNTA: En un DTD, #IMPLIED implica que el atributo:
A: Es obligatorio.
B: Es opcional.
C: Es fijo.
D: Ninguna de las anteriores es correcta.
RESPUESTA: B
EXPLICACION: En un DTD, el valor por defecto de un atributo puede ser #REQUIRED (obligatorio, debe aparecer siempre), #IMPLIED (opcional, puede omitirse sin valor por defecto), #FIXED "valor" (fijo, siempre tiene ese valor) o un valor literal como valor por defecto. Por tanto, #IMPLIED significa que el atributo es completamente opcional: si no se incluye, no hay valor predeterminado.

PREGUNTA: Las anotaciones con <![CDATA[ deben cerrarse con:
A: ]!>.
B: !]>.
C: ]]>.
D: ]!]>.
RESPUESTA: C
EXPLICACION: Las secciones CDATA (Character DATA) en XML permiten incluir texto que no debe ser interpretado como marcado. Se abren con <![CDATA[ y se cierran obligatoriamente con ]]>. Su uso más común es incluir código con caracteres especiales como <, > o & sin necesidad de usar entidades como &lt; o &gt;. El contenido entre ambas marcas se trata como texto literal.

PREGUNTA: Las marcas de cierre:
A: Pueden contener espacios.
B: Deben estar acompañadas de los signos "[" y "]" para delimitarlas.
C: No requieren el uso de los signos "<" y ">" para delimitarlas.
D: Deben estar acompañadas de los signos "<" y ">" para delimitarlas.
RESPUESTA: D
EXPLICACION: En XML, todas las etiquetas (tanto de apertura como de cierre) deben usar obligatoriamente los símbolos < y > como delimitadores. Las etiquetas de cierre añaden además la barra: </etiqueta>. No pueden contener espacios en el nombre ni usar otros delimitadores. Esta es una regla fundamental de un documento XML bien formado (well-formed).

PREGUNTA: Selecciona el elemento XML correcto:
A: "<Texto></Text>"
B: "<.Texto></.Texto>"
C: "<Texto$></Texto$>"
D: "<Texto />"
RESPUESTA: D
EXPLICACION: La opción D muestra un elemento vacío con sintaxis de autocierre, completamente válida en XML. La A es incorrecta porque apertura y cierre usan nombres distintos (Texto vs Text). La B es inválida porque los nombres de etiqueta no pueden empezar con punto. La C es inválida porque el símbolo $ no está permitido en nombres de etiquetas XML (solo letras, dígitos, guion, guion bajo y punto, sin empezar por dígito).

PREGUNTA: Parser es:
A: Un analizador sintáctico.
B: Un modelo de base de datos No-SQL.
C: Un nodo de XPath.
D: Ninguna de las anteriores, Parser no existe.
RESPUESTA: A
EXPLICACION: Un parser (analizador sintáctico) es el componente software que lee un documento XML y verifica que cumple las reglas de sintaxis del lenguaje. Los parsers XML pueden ser validadores (comprueban además la conformidad con un DTD o Schema) o no validadores (solo verifican que el documento está bien formado). Ejemplos conocidos son Xerces (Apache), MSXML (Microsoft) o el integrado en los navegadores modernos.
